# DaVinci Resolve Free — Computer Use 編集

Resolve の GUI を操作して編集する。Resolve MCP、外部スクリプティング API、Studio ライセンスには依存しない。説明は日本語を基本とする。
通常編集を支援するスキルであり、Studio 固有の AI 機能・エフェクト・コーデックを無料版へ追加するものではない。

本版は実験版。単一素材への Text+ 日英テロップ作成、保存、MP4 出力を1環境で確認した。複数素材の連結・映像と別素材音声の組み合わせ・速度変更・SRT読み込み・フェードは実地検証未完了。手順の存在を動作保証と扱わず、依頼された操作ごとに結果を確認する。

## 操作環境

1. 利用可能な `computer-use:computer-use` スキルを読み、付属の guidance と confirmations に従う。API の引数は必要時にその api ドキュメントで確認する。
2. その Windows 用 `node_repl` で `@oai/sky` を初期化し、返されたアプリ・ウィンドウから Resolve を一意に選ぶ。ブラウザ専用 CUA が native apps disabled と表示しても、Windows 用 Computer Use の可否とは分けて判定する。
3. 画面でエディション、バージョン、UI 言語、開いているプロジェクト、ページ、タイムラインを確認する。実行ファイルのバージョンだけでは Free/Studio を断定しない。
4. 最小化なら選択済みウィンドウを activate して再取得する。ロック画面、認証、権限要求を自動で突破しない。
5. Windows 用 Computer Use が実際に呼べなければ、編集メモや SRT など可能な準備だけ行い、GUI 操作は未実施と報告する。別の入力注入方式や Resolve API へ無断で切り替えない。

Resolve の画面操作は Computer Use に統一する。通常のファイルツールは、素材のメタデータ確認、SRT 作成、成果物の検証に利用できる。Resolve の Console へのコード投入、DB の直接変更、MCP サーバー導入はこの経路に含めない。

## 作業開始

- 素材パス、編集意図、納品要件を会話から特定する。重要な不足のみ質問し、指定済みの条件を聞き直さない。
- 指定素材に絞って存在・読み込み可否・映像/音声・長さ・fps を調べる。必要なら既存の ffprobe を使用する。ツール導入やモデル取得を自動で追加しない。
- 作業するプロジェクトとタイムラインを UI で照合する。開いているという理由だけで別案件を編集対象にしない。
- 新規依頼は別名のタイムライン、既存編集は原則としてタイムラインの複製を UI で作成し、そのコピーが開いたことを確認してから編集する。複製が使えない場合は安全な作業コピーを作れるか確認する。
- 元素材を保ち、既存の fps、カラー管理、他トラックの内容を勝手に変更しない。ファイルを削除する場合は対象と理由を示して事前承認を得る。
- 複数素材や映像と音声の別利用では、素材名・ソース範囲・映像/音声の別・配置先時刻・期待尺を対応表にする。指定があればそのまま使い、意図的な音声差し替えを「同期ずれ」として元へ戻さない。詳細は [references/ui-workflows.md](references/ui-workflows.md) の「複数素材・映像と音声の別配置」を参照する。

## 編集と確認のループ

画面観察 → 一つの入力 → 再観察を繰り返す。現状を見ずに座標を連打するマクロは作らない。

- アクセシビリティ要素が得られれば利用し、得られなければ最新スクリーンショットを読む。座標、screenshotId、要素番号を状態変更後に使い回さない。
- メニューと Inspector の数値欄を優先する。キーボード割当はユーザー環境で異なるため、ショートカットを確認せず使わない。
- 数値・字幕入力前は対象欄のフォーカスを確認する。入力後に表示値、選択クリップ、アクティブトラックを読み返す。
- トリム/移動前にスナップ、リンク選択、トラックロック、リップルの影響範囲を確認する。ドラッグだけでフレーム精度を推測しない。
- メニュー、モーダル、別ウィンドウが現れたら、その状態を取得してから続ける。
- 失敗やタイムアウト後は、追加済みの字幕・クリップ・ジョブを確認してから再試行する。状態不明の変更を繰り返さない。
- 字幕入力・タイムコード・トラック指定で問題が出たら [references/ui-workflows.md](references/ui-workflows.md) の「実機で確認した注意点」を読む。座標やキーを過去の環境からそのまま流用しない。

時刻は素材の相対時刻、素材タイムコード、タイムラインタイムコードを区別する。タイムライン開始が 01:00:00:00 でも SRT のゼロ起点と同一視しない。fps は必要に応じて 30000/1001 等の有理数と DF/NDF を記録する。作業メモの範囲は開始を含み終了を含まないものとし、UI の Out 点が最終フレームを含むかは実尺で確かめる。

## 操作別の方針

詳しい手順が必要な操作だけ [references/ui-workflows.md](references/ui-workflows.md) を読む。

| 目的 | 無料版 GUI での経路 | 仕上がりの確認 |
|---|---|---|
| 素材配置・カット | Media Pool → ソース範囲 → Edit ページで配置/トリム | 冒頭・末尾フレーム、尺、配置順 |
| 一定速度・逆再生・静止 | クリップの速度設定や Retime Controls | 速度、尺、音声同期とピッチ |
| 速度ランプ | Retime Controls と Retime Curve | 変化区間と補間を再生確認 |
| 字幕 | UTF-8 SRT の読み込み、または字幕トラックの手入力 | 実際の配置、誤字、表示時刻 |
| 装飾テロップ | Text / Text+ を映像トラックへ追加し Inspector で設定 | フォント、行分け、画面内の位置 |
| 映像のつなぎ | Effects の利用可能なビデオトランジション | 境界両側の映像と長さ |
| 音のつなぎ | オーディオトランジション、または重ねた音のフェード | 中央で両方が聞こえること、音量 |
| 書き出し | Deliver の設定と今回のジョブだけ実行 | 完了表示、ファイル、映像/音声/字幕 |

Studio 要求、ウォーターマーク、使用不可表示が出た機能を完成扱いにしない。Speed Warp 等に依存せず、実機で利用可能な補間を選ぶ。機能の変更が表現や要件を変える場合は、その差を伝えて判断を求める。

自動文字起こしが必要なら、まず支給 SRT/原稿または既に利用可能なローカル文字起こし環境を確認する。無料版の自動字幕を前提にしない。ローカル環境もなければ、実行に必要な選択肢を提示する。外部サービスへの素材送信、有料 API、モデルの新規ダウンロードを黙って行わない。SRT を生成しただけでは Resolve への字幕追加は未完了。

## セリフのテロップで毎回行うこと

セリフに合わせたテロップの作成・修正では、毎回 [references/ui-workflows.md](references/ui-workflows.md) の「発話同期と長文テロップ」を読み、全区間に適用する。

- 文字起こしの時刻をそのまま採用せず、最終タイムラインの音声と照合して発話開始に合わせる。カット・音声差し替え・速度変更後は時刻を再計算する。
- 日英2段の Text+ 指定では既存の2つのタイトル設定を再利用し、対応する日英の開始・終了を揃える。字幕トラックへ置き換えない。
- 長文は意味と発話の区切りで分割するか、同じ Text+ 内で改行する。全テロップの左右・上下の余白、日英の重なり、背景を実際の縦横比で確認する。
- 発話前の非表示、発話中の表示、語尾までの表示を確認し、素材の語尾や余韻をテロップに合わせて切らない。聴取未確認なら波形による調整と区別して報告する。

## 保存・納品

まとまった編集ごとに UI から保存し、未保存表示やエラーダイアログを確認する。作業記録が必要なら小さな一つのメモに、プロジェクト/コピー名、素材、fps、実施済み、検証済み、次の操作をまとめる。

書き出し依頼では保存先、解像度、fps、映像/音声形式、範囲、字幕の焼き込み/別ファイルを確認する。既存ファイルと衝突しない名前を使い、Render All で他のジョブを巻き込まない。Resolve プロジェクトは通常プロジェクトライブラリに保存されるため、存在しない .drp パスを納品先として報告しない。.drp が必要なら UI で別途エクスポートする。

プレビューはカット境界、速度変化、字幕開始/終了、フェード中央、最後のフレームを重点的に確認する。再生できても音声を聴取する手段がなければ「聴取未確認」と明記する。メーターだけで音質を保証しない。

完了報告では編集対象、保存状態、出力ファイル、実際に確認した項目、未検証/未完了を区別する。レンダー終了表示だけでなくファイルの存在と読み込みを確認し、可能なら尺・映像・音声を調べる。スキルの構文検証と実際の編集テストも区別する。
