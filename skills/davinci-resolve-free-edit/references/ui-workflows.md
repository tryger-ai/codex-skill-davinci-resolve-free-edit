# GUI 編集の実施ガイド

メニュー名は目印であり、言語や版によって表示が異なる。各操作は最新画面を見て一つずつ行う。以下の節全体を一度のツール呼び出しで実行しない。

## 素材・作業コピー

Media Pool のタイムラインを選び、コンテキストメニューで Duplicate Timeline に相当する項目を確認する。作成したコピーに識別しやすい名前を付け、タイムラインヘッダーで対象を確かめる。既存プロジェクト全体の複製や DB 操作は不要。
素材取り込み時の fps 変更ダイアログは即座に承諾しない。新規タイムラインの目的と素材fpsに合わせて判断し、既存編集のレートは維持する。

## カット・トリム

1. 新規配置はソースビューアで必要な開始/終了を設定してから対象トラックへ置く。映像と音声の両方が必要かを確認する。
2. 既存クリップは作業コピー上で再生ヘッドの時刻と選択を確認し、Split/Blade またはトリムを行う。リンク音声とロック状態も確認する。
3. リップル操作は後続クリップや字幕も動かし得る。通常トリムとの違いを意図に照合する。
4. UI に表示された In/Out/Duration と前後のフレームを確認する。範囲指定の包含規則による1フレーム差を放置しない。

## 複数素材・映像と音声の別配置

この経路は初版では未検証。以下の確認点に沿い、実際の画面で操作可能か確かめる。

1. 素材ごとにソースの範囲と必要なストリームを特定する。映像用・音声用の範囲を別に記録し、配置先と期待尺を計算する。
2. UIで映像のみ／音声のみを配置する操作を確認する。利用できなければ、作業コピー上でリンクと選択対象を確かめて編集する。片方の移動で他方が連動していないことを検査する。
3. Aの映像＋Bの音声では、Aの元音声が重複していないか、Bの映像が意図せず追加されていないかをトラック単位で確認する。
4. 異なる長さは無断で伸縮しない。尺合わせを任されていれば編集意図に沿って調整し、映像だけの延長、無音、セリフ切断が生じていないか検査する。
5. つなぎ目の前後フレーム、隙間・重複、映像と音声の対応を確認する。発話中の口の動きと音声が一致するかは、確認できた範囲だけ報告する。

## 速度設定

一定速度は Change Clip Speed に相当する設定で値を指定する。Ripple Timeline、Reverse、Freeze、Pitch Correction 等は実際に見える項目だけ使用し、目的に合わせる。
ランプは Retime Controls で速度区間を作り、Retime Curve で速度曲線と補間を確認する。複数の固定速度クリップを並べただけの状態を滑らかなランプと呼ばない。
Speed Warp のように Studio が要求される方式を選ばず、使用可能な方式で画質を確認する。極端なスローで補間破綻が残る場合はその限界を伝える。
速度変更は字幕確定より先に行う。速度確定後、最終タイムラインの発話位置で字幕を合わせる。

## SRT 字幕と Text+

SRT は連番、`HH:MM:SS,mmm --> HH:MM:SS,mmm`、本文、空行を持つ UTF-8 テキストとする。原稿があっても音声に合わせていなければ時刻は仮値と明示する。

- UI の字幕インポート、または Media Pool の読み込みから字幕トラックへ配置する。実際に見つかった経路を使い、隠れたメニューの存在を推測しない。
- まず先頭付近の字幕を一つ表示し、ゼロ起点とタイムライン開始時刻のずれがないか確認する。末尾も確認して、固定オフセットと速度変更によるずれを分ける。
- 字幕トラックのスタイルと各字幕の上書きを区別する。フォントがなければ代替名を説明する。日本語文字化け、折り返し、縦動画の余白を確認する。
- Text/Text+ は別の映像タイトルとして配置する。字幕トラックと同じ編集・SRT 書き出しができるとは扱わない。SRT 納品も必要なら対応する字幕データを別途保つ。
- Text+ の再利用は、ユーザーが指定したテンプレートや今回の設定から行う。他案件のフォント・配色を勝手に適用しない。

## 発話同期と長文テロップ

セリフのテロップを扱うたびに、次の順で全区間を確認する。特定の作品の時刻、fps、座標、音量閾値を次の素材へ固定適用しない。

### 発話位置を確定する

1. 映像・音声のカットと速度を確定し、実際に使う音声のソース In、タイムライン In、fps、速度を確認する。等速の区間は、同一の時間単位で「表示時刻 = 音声クリップのタイムライン In + (素材内の発話時刻 − 音声クリップのソース In)」とする。別素材の音声はその音声の配置を基準とし、速度変更は区間ごとの対応から求める。
2. ASR（文字起こし）の単語時刻は候補として扱う。語頭に長い無音が含まれる場合があるので、再生音声と波形を照合する。発話より先に表示しないよう開始フレームを決め、語尾を含む終了フレームを決める。長い無音に前のテロップを残さない。
3. 直接聴取できなければ、既存の文字起こしと波形・RMS等で候補を絞る。息、BGM、効果音を発話と断定しない。不明区間は未検証として残し、波形だけで「聴取確認済み」「完全同期」と報告しない。
4. Text+ の開始・終了を変更後、編集インデックス等の数値で読み返す。隣接タイトルの境界操作がロール編集になり、前のタイトルも伸びる場合がある。両側の開始・終了、意図しない重複、日英の対応を確認し、対象だけのトリムに修正する。
5. テロップだけの修正では素材の In/Out、音声、尺を保持する。最後の単語のASR終了時刻を素材のカット点にせず、語尾と必要な余韻が残っているか別に確認する。

### 長い文章を収める

- 日英2段の指定では、日本語用・英語用 Text+ のフォント、サイズ、色、縁取り、背景、基本位置を引き継ぐ。各組の開始・終了を同一にする。
- 意味の区切りと発話位置が分かる長文は複数の表示区間に分け、各区間に対応する日本語と英訳を付ける。文字数で均等分割したり、分割後の表示時間を均等配分したりしない。短すぎて読めない分割は避ける。
- 一つの発話として見せたい場合や自然に時分割できない場合は、長い側の Text+ 内を二行などに改行する。例：英語の `It's not because` と `I'm bad at drawing,` を別行にする。改行はInspector本文にも実際に反映されたことを確認する。
- 「日本語＋英語の2段」と「各言語内の改行」を区別する。改行後も日英が重ならず、背景が文字を覆い、画面の左右・上下に余白があるか確認する。文字数だけで収まりを判断しない。
- 分割・改行を優先し、必要な場合に限り位置・行間・サイズを最小限調整する。変更した設定を確認し、単に小さくして読みにくくしない。

### 保存前の確認

全テロップについて開始直前、開始、発話中、終了直前・直後を確認する。プレビュー更新が遅れたら表示タイムコードが移動先に一致してから判定する。全区間の見切れ・重なり、日英の時刻一致、素材末尾の保持を確認して保存し、聴取・波形・画面のどこまで検証できたかを報告する。

## 映像・音声トランジション

映像は利用可能な Cross Dissolve などを境界に配置し、Inspector 等で尺と位置を確認する。両素材に未使用の前後フレームがない場合は、トリムやつなぎ方の調整が必要となる。素材の尺を越えるフレームを想定しない。
音声は音声用クロスフェードを使うか、別トラックで時間を重ねてフェードアウト/インする。離れた音の端を下げただけでは連続した混合にならない。リンク音声を移動した場合は映像との同期を再確認する。
フェードの長さを映像と音声でそれぞれ確認し、再生/聴取できた範囲を記録する。

## Deliver と保存

1. 画面の出力範囲、ファイル名、フォルダ、形式、コーデック、解像度、fps、音声出力を読む。UI にないエンコーダーや無料版で使えない条件を指定しない。
2. 字幕は焼き込み、別ファイル、不要のいずれかを依頼に合わせる。字幕トラックの有効状態も確認する。
3. 今回のジョブを追加し、そのジョブだけをレンダーする。既存キューの削除や一括開始は不要。
4. 処理が長い場合は進捗を間隔を置いて読み取る。タイムアウト後に同じジョブを追加しない。
5. 完了表示と出力ファイルを確認する。ファイルのサイズだけで成功とせず、再生またはメタデータで尺・ストリームを確かめる。

## 小規模な実機検証

スキル設定のみの依頼で、開いている制作案件をテスト編集しない。編集検証を行う場合は、指定されたテスト素材と独立したプロジェクト/タイムラインを使う。
短い素材で取り込み → 一箇所のトリム → 速度変更 → 一つの字幕 → 映像/音声のつなぎ → 保存 → 短い書き出しを確認する。未実施の操作は未検証のまま報告する。テスト後のファイル削除も承認なしには行わない。

## 実機で確認した注意点

以下は Resolve 20 日本語UIの1環境で観察した挙動。他環境の固定操作として扱わない。

- タイムコード欄では、ダブルクリックで選択した値へ直接文字入力すると確定できた。Ctrl+Aはクリップ全選択へ届く場合があった。字幕本文欄のCtrl+Aも、欄のフォーカスを確認してから使う。
- テキスト欄や数値欄で、入力後の値と適用先を読み返す。欄からフォーカスが外れるまで確定しない場合がある。
- タイトルのコピー・貼り付け先は、ソースパッチとは別のトラック選択に依存した。貼り付け前後でトラック、クリップ数、開始・終了、既存字幕が上書きされていないかを確認する。
- クリップ長のショートカットが別アプリに奪われた事例があった。その環境ではコンテキストメニューの「クリップの長さを変更」を使った。別アプリが開いたら追加入力せず対象ウィンドウを取り直す。
- ドラッグが選択だけになり移動しない場合があった。同じドラッグを繰り返さず、数値入力・メニュー・範囲指定で代替できるか確認する。
- Inspectorのドロップダウン上でスクロールすると選択値が変わる場合があった。スクロール後は関連設定も読み返す。
- ウィンドウの復元・最大化・モーダル表示後は、スクリーンショットと座標の基準を取り直す。
- Text+をゼロから再現する依頼では、標準の空タイトルからフォント・文字サイズ・色・レイアウト・シェーディングを設定する。参照タイトルのコピーと区別する。自身が作成したスタイルの後続区間への複製は依頼に合わせて使える。
- Text+の色や縁取りはTextタブだけで完結しない。Shadingの各要素の有効状態、色、Opacity、Outlineの太さ、背景の対象単位を確認する。
